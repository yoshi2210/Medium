あなたは、現代美術館のエキシビション・カタログとテック系エディトリアルの両方を手がけてきた
アートディレクター兼クリエイティブ・エンジニアです。これから **Braindumper** という人物の
個人ランディングページを、単一の自己完結HTMLファイルとして設計・実装してください。

## 0. 人物とページの目的

- 名義: **Braindumper**
- 正体: メディアアーティストであり、同時に「論客」— テキストで思考を公開し、批評で格を高めていく人物。
- ページの役割:
  1. 第一印象で「作品を作る人間であり、かつ思考する人間である」という二重性を刻印する
  2. note / Zenn / Medium 的にテキスト(エッセイ・批評)を連ねていく **Writing インデックス** が主戦場
  3. ゆくゆくはアプリやツールも並べられる **Apps セクション** を最初から構造として持つ
- トーンは「静かな威圧」。売り込まない。展示する。

### コピーの鉄則(重要)
- **ポエムを書かないこと。** 自己陶酔的なアフォリズム、詩的な体言止め、抽象的な宣言文は全て禁止。
  威圧感は言葉ではなく、組版・空間・実装の精度で出す。
- テキストは全て事実ベースで書く: 何をしているか、どこで公開しているか、何が置かれているか。
- 判定基準: その一文を初対面の編集者に音読されて恥ずかしくないか。

## 1. コンセプト:「暗闇の美術館 × 組版された論考」

黒を背景色としてではなく **展示空間** として扱うこと。作品とテキストは暗闇から浮かび上がる。
池田亮司のデータ・ミニマリズム(黒白の極限コントラスト、グリッド、走査線、生データの美学)と、
新聞・学術誌のエディトリアル組版(番号付き目次、罫線、余白の呼吸)を一つの画面で衝突させる。

## 2. デザイン次元 — 個別指示

### Typography(最重要)
- **二重書体システム**を採用すること。これはこのページの思想的核である:
  - 論客の声 = **セリフ体**(見出し・声明文)。日本語は明朝の中でも骨のあるもの(例: Shippori Mincho)、
    欧文はエディトリアル系ディスプレイセリフ(例: Fraunces の光学サイズ活用)
  - アーティスト/機械の声 = **モノスペース**(ラベル、番号、日付、メタデータ。例: IBM Plex Mono)
- 禁止: Inter, Roboto, Arial, Open Sans, Lato, システムフォント, そして安易な Space Grotesk
- ウェイトとサイズは**極端に**振ること。400 vs 600 ではなく 200 vs 800。サイズ差は3倍以上のジャンプ。
- 日本語の縦書き(writing-mode: vertical-rl)を一箇所、構造的に効く場所で使うこと。飾りではなく建築として。

### Color & Theme
- 基調: 純黒ではなく **#0a0a0a 前後のニアブラック**。インクの黒。
- 文字: 純白ではなくわずかに沈めたオフホワイト。長文可読性を最優先。
- アクセントは **一色のみ**。信号のような赤(朱に寄せない、警告灯の赤)。
  使用箇所は全画面で5〜8箇所に制限し、「ここぞ」でしか光らせない。
  弱気に散らした配色より、支配色+鋭い差し色が圧倒的に強い。
- 全カラーを CSS 変数(:root)で定義し、トークンとして運用すること。
- 禁止: 紫グラデーション、グラスモーフィズム、意味のないネオン。

### Background
- ベタ塗りで済ませないこと。ただし派手にもしないこと。以下を**低輝度で**レイヤーする:
  - 1px のヘアライン・グリッド(美術館の展示ケースの精密さ)
  - 微細なノイズ/データレイン的な canvas 演出(hero のみ、輝度は暗闇を壊さない範囲)
  - セクション番号の超大型ゴースト数字(背景装飾としての組版)

### Motion / Interaction(技術的権威性の中核)
受賞級サイトの定番演出(GSAP SplitText / Lenis / Three.js 系)と同等の体験を、
**依存ライブラリゼロの手書きバニラJSで実装する**こと。view-source が最大の証明になる。

- ページロード時の一回のオーケストレーション(staggered reveal)に最大の演出コストを割く
- **スクランブル解読**: モノスペース要素(=機械の声)だけが、出現時とホバー時に文字化けから解読される。
  セリフ体(=論客の声)は決して揺らがない — この非対称が思想
- **行単位ワイプ・リビール**: 声明文は overflow:hidden + translateY のライン分割で立ち上がる
- **ライブ・テレメトリ**: 画面下端に JST時計 / スクロール% / 現在セクション / ポインタ座標を常時表示。
  上端にはスクロール進捗の赤い1pxヘアライン
- **カスタムカーソル**(pointer:fine のみ): 赤いドット+遅延追従するリング。リンク上でリングが開く
- **背景キャンバスのポインタ反応**: データレインのグリフはポインタ近傍だけ照明が当たり、至近は赤く灯る
- **生きている展示**: Works のジェネラティブSVGは可視中のみ低頻度で描き換わり続ける
- ナビリンクはマグネティック・ホバー(ポインタ方向へ数px吸着)
- 全面に微細なフィルムグレイン(SVG feTurbulence、不透明度5%以下)
- ホバーは「照明が当たる」比喩で統一(輝度上昇、アクセント色の点灯、罫線の伸長)
- prefers-reduced-motion を必ず尊重すること(装飾を止めてもコンテンツが全て見えること)
- console.log に署名を残す(view-source した人への挨拶)

## 3. 情報設計(セクション構成)

番号付きセクションとして構成する。番号(00, 01, …)はモノスペースで刻印すること。

1. **Hero** — 名義 BRAINDUMPER の超大型タイポ、肩書き(MEDIA ARTIST / CRITIC)、日本語の一行声明
2. **Statement (00)** — 論客としての宣言文。大きな明朝で、詩ではなく断言として組む
3. **Writing (01)** — 主戦場。番号付きインデックス(001, 002, …)。各行: 番号 / 日付 / タイトル / タグ / 掲載先。
   note・Zenn・Medium への外部リンクを前提とした構造にし、行の追加だけで運用できる HTML にすること
4. **Works (02)** — メディアアート作品。画像素材は使わず、CSS/SVG によるジェネラティブな
   モノクロビジュアルをプレースホルダとして自前生成すること
5. **Apps (03)** — 将来のアプリ置き場。「IN DEVELOPMENT」の状態表示を持つカード構造だけ先に建てる
6. **About / Contact (04)** — 短い経歴と接続先(SNS, note, Zenn, Medium, GitHub)。フッターに座標情報的なメタデータ

## 4. 技術要件

- 単一 HTML ファイル、依存は Google Fonts のみ。JSライブラリ・フレームワーク・ビルドは一切禁止。
  これは制約ではなく差別化戦略である(定番の GSAP+Lenis+Three.js スタックとの対比)。
- セマンティック HTML、レスポンシブ(モバイルでは縦書き・グリッドを適切に降格)。
- 長文コンテンツの行長は全角35〜40字相当に制御。line-height は日本語本文で 1.9 前後。
- コントラストは WCAG AA を満たすこと(暗闇の演出と可読性を両立させる)。
- コンテンツはプレースホルダでよいが、「ダミーです」と分かる書き方をせず、実在感のある仮テキストを書くこと。

## 5. 進め方

コードを書き始める前に、採用する書体・カラートークン・モーション設計を宣言してから実装すること。
迷ったら「暗闇の美術館でこれは成立するか」「論文の組版としてこれは正確か」の二つで判定せよ。
